# Mac and iPhone widgets

Build native small, medium, and large WidgetKit widgets for macOS 14+ and iOS 17+.
Retain the existing menu-bar app as the Mac data source. The signed Mac app
embeds a widget extension and publishes allowlisted summaries (provider/account
display names, quota percentages, balance text, health, timestamps) into its App
Group and optionally a single record in the user's private CloudKit database.
Never serialize provider credentials, raw subprocess output, or error bodies.
The iPhone companion app and widget fetch the same record and cache it locally.
Both devices must use the same iCloud account. No public status pages.

Small: compact status rows for up to two providers. Medium: a prominent donut
and its quota windows. Large: up to three provider donuts and an explicit
additional-provider count. iPhone Lock Screen supports rectangular and inline
compact status. Both show aggregate
connection health and snapshot age. A timestamp is the source check time, never
the download time. Missing, corrupt, future-dated, and stale data cannot be green.
Use native system fonts and semantic foreground/background colors, restrained
slate accents, support dark/tinted widget rendering and accessibility labels.

Mac sync is opt-in, visible in the menu. It is throttled and serial, with bounded
retry; disabling stops future uploads (it does not delete already-synced data).
The phone offers a manual sync action and actionable iCloud setup/error states.
Widget reload requests are hints to WidgetKit, not real-time guarantees.

Physical-device deployment requires Apple Developer membership, registered App
Group/CloudKit identifiers, signing profiles, and a CloudKit production schema
for distribution. Simulator/unsigned builds must not claim live iCloud success.
The existing personal binary release remains working until signed deployment is
verified. Do not publish an unsigned widget build as a finished device release.
